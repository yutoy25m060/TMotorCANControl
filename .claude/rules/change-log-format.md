# 変更記録フォーマット

## 保存先
`.ai/logs/YYYY-MM-DD_XX_<slug>_YY.md`

- YYYY-MM-DD: 作業完了日
- XX: 連番（同日複数記録の場合は `_2`, `_3` と連番）
- slug: 変更内容を表す短い識別子（kebab-case、半角英数のみ）
- YY: 連番（同一変更内容の場合は `_2`, `_3` と連番）

## 必須セクション構成

1. **冒頭メタ情報**
   - 日時（YYYY-MM-DD HH:MM）
   - 対象ファイル（箇条書き）
   - 種別：`機能追加` / `バグ修正` / `リファクタリング`

2. **設計判断と理由**
   - なぜこの実装を選んだか
   - 検討した代替案と却下理由
   - トレードオフの明示

3. **未対応・既知の課題**
   - 今回のスコープ外とした項目
   - 発見した派生課題
   - 将来の技術的負債

4. **テスト状況**（チェックリスト形式）
   - [ ] 単体テスト実行
   - [ ] 統合テスト実行
   - [ ] 手動確認
   - [ ] リグレッションテスト
